# 详细使用文档与注意事项

## 直接获得自动推荐（v0.3）

启动后在“今日推荐”点击“添加目标”，填写想完成什么、怎样算完成、领域、优先级与可选期限。保存后后台自动开始，本地模型加载时先显示标有“规则建议”的卡片；无需点击重新推荐。页面约每5秒检查结果，输入变化会由后端独立调度，网页关闭后只要服务仍在运行就会继续工作。

点击“采纳为今日重点”才会加入行动。采纳的预计时间计入当天计划预算，不代表已经完成。完成任务后，系统参考已有完成记录继续推荐与该目标相关的下一步；不会自行宣告目标已经完成。“今天忽略”会隐藏当前阶段的建议到当天结束，目标内容或阶段发生变化后可能重新参与推荐。建议更新后，旧卡片的采纳请求会被拒绝，请审阅当前版本。

在“模型与设置”调整每日时间预算、自动推荐开关、本地推荐模型和相同数据重评间隔。默认90分钟预算、6小时重评；输入变化会更早触发。Laya用于现有候选的类型化排序，Ollama能够细化目标步骤。模型请求超时或格式错误后保留规则建议，至少5分钟后才自动重试。服务空闲每30秒检查一次；当前模型任务忙时排队等待下一轮检查。

自动推荐只发送到本机模型。设置中的远程接口继续用于手动决策，需要逐次预览确认。系统目前未接入日历，不知道真实空闲时段；预计分钟数是计划值，需要你按实际情况调整。服务停止后不再安排新任务；已发给本机模型服务的推理可能继续完成，但不会自动执行推荐行动。

主动推荐的来源、模型调用快照和反馈属于私有数据，包含在v2备份中；旧v1备份仍可恢复到空目录。默认脱敏摘要不包含目标和建议自由文本。

## 使用手动决策空间

按 README 安装并启动，打开本机8765端口。新空间没有预填个人记录或假数据。可以不配置模型，先用一个真实、具体、影响较小的问题走完整流程。

在“决策空间”新建问题：写出2—8个可执行方案、明确成功标准与回看时间，先选出你自己倾向的方案。成功标准应在看到结果前确定，例如“周五前保存一个能运行的原型”，避免结果出来后重新定义成功。

需要模型时，在详情里选择本地 Ollama、Laya 或云端接口，再预览发送字段。模型返回后检查依据与限制，最终可以采用原始选择、模型选择或其他给定选项。较高影响或不可逆选择必须填写理由。确认后会生成行动任务。

行动完成后，回到决策详情，对照原标准记录达到、未达到、部分达到或无法判断。任务勾选不替代结果判断；没有观察到的结果不要补成“失败”。已记录结果固定，新的评估建立新决策。暂时放下的事项保留原因与历史。

## 指标与观察

一次先定义少量确有用途的指标。填写名称、单位、上下界、方向、目标（目标型指标）和所选窗口期望的记录次数。上界不是普遍最佳值，应依据你自己的目标选取。

记录时间使用浏览器本地时区，后端统一存UTC。历史窗口按当前时刻向前滚动，靠近边界的记录可能跨出窗口。记录被更正后，旧记录仍在私有备份里，统计只采用最新有效记录。页面的历史更正入口展示当前窗口内的有效观察；所有历史都在备份中。

越低越好和目标型指标有不同公式，详见蓝图。不要用睡眠、收入、情绪等不同维度的范围内得分直接比较人，系统不生成人生总分。一次主观记录并不具备仪器测量的精度。

## 个人资料与复盘

将自己的短笔记或有权使用的摘要粘贴进资料库，保留来源。系统做词法匹配，优先使用与问题相关的词；没有匹配不会编造引用。当前使用每份资料的前1800字，长文宜拆成有标题的短段。

资料和模型输出都是待核查内容。模型可能受到不实材料或提示注入影响；系统限制了输出选项和执行权限，但不能保证事实正确。核查依据后再确认。

复盘页选择7/30/90天，写出发生了什么、信息不足之处和下一件要调整的事。保存时冻结当时的统计快照。决策过程报告使用全部历史，指标使用所选窗口，页面有明确提示。采用率只表示人选了模型推荐方案，不表示建议正确；当前真实适配器不生成可计分的成功概率，因此相应损失保持为空。

## 模型配置与资源

Ollama 默认 qwen3:8b，需要服务已有对应模型。可选更小模型，但结构化输出及建议质量必须实际检查。更换名称后在设置页刷新连接；列出模型只证明服务可连接，不证明推理可成功。

Laya 安装独立可选，使用固定 revision `1720e3e3357cfe1e281542e223f8273b0890ca34` 的 `convaiinnovations/laya-multilingual`。本地权重路径优先于Hub下载，该目录的真实性需用户自行确认；回执中的revision表示请求配置，并不对任意本地目录内容做哈希认证。默认CPU，CUDA需要可用驱动和PyTorch环境。超出输入预算会拒绝建议，缩短背景或使用其他模型。首次模型加载可能超过一分钟；当前调用超时为Laya150秒、HTTP120秒。

云端基础地址需与服务文档一致，应用会附加 `/chat/completions`。没有自动尝试其他地址或隐藏重试。每次远程发送均需预览；更改内容、模型或服务地址后必须重新预览。接口密钥仅用于请求头，也可通过 `QONE_CLOUD_API_KEY` 环境变量提供；环境变量优先，页面清除不能移除进程环境变量。设置文件保存为权限0600的本机明文文件，不是密钥保险库。

模型返回格式不兼容、未知选项或连接失败时，会显示错误并保留失败记录。你仍可直接作出自己的选择。不要把服务密钥写进问题或笔记，这些自由文本属于私有备份内容。

## 数据、备份和恢复

默认目录：`~/.local/share/q-one`，可用 `QONE_HOME` 修改。

- `decisions.jsonl`：决策原始事件；不要手动编辑。
- `app.sqlite3`及其可能的`-wal`/`-shm`文件：任务、指标、观察、资料、复盘、模型调用。
- `settings.json`：模型配置和可选密钥。

页面“私有备份”包含原始文本、事件、资料和调用信息，**不包含设置及密钥**。它可用于空空间恢复，网页上传上限4MB。超过限制时，停止程序后完整复制整个数据目录到可信位置，再使用 `QONE_HOME` 指向该副本启动；不要在运行中只复制SQLite主文件。

恢复步骤：先保存现有空间的备份，停止程序；使用一个新的空目录启动；在设置页选择“从备份恢复”。恢复会检查事件哈希、状态转移和数据关联，拒绝覆盖已有数据。恢复中断时会保留私有待恢复文件，下一次启动先重放完成恢复。若备份或待恢复文件损坏，保留原件，改用另一个空目录从已知良好的备份恢复，不要反复编辑原始账本。

导出摘要会移除自由文本、精确时间、选项名及原始关联ID，保留领域、状态、观察数量和分数。它不是形式化匿名化，分享前仍要检查。已删除资料不再用于新检索；既有调用中的引用片段快照仍属于历史和私有备份。

## 当前注意事项

本版本适合本机单用户，启动入口只允许回环地址，没有账号登录、多用户隔离或服务器部署方案。不要把端口转发到公网。具有本机账号权限的软件仍可能读取数据；应用没有磁盘加密和防恶意本机进程能力。

事件哈希链可以发现普通篡改和截断破坏；持有全部文件写权限的人可以重建链，它不是签名、可信时间戳或外部审计锚。

只使用单个服务进程和一个数据目录，避免同时运行多个实例。决策事件有跨进程文件锁，其他界面状态及模型并发限制按单进程设计。遇到端口占用改端口，不能随意停止其他项目服务。

网页和旧CLI的数据格式分开。早期 `qone-life --data-dir .life-data init` 等命令只处理旧观察日志，不会验证、导出或迁移网页SQLite；网页备份请使用设置页或停止后复制完整目录。

## 常见问题

| 现象 | 处理 |
|---|---|
| 页面打不开 | 确认启动窗口仍在运行，地址和端口一致；如冲突可用`--port 8766` |
| 模型连接失败 | 核对地址、模型名、内存与服务状态，先手动决定也能完成流程 |
| Laya运行失败 | 在运行应用的同一虚拟环境安装laya，核对权重完整性与CPU/CUDA配置 |
| 已配置云端但失败 | 服务需支持JSON结构化输出；查看HTTP状态，按供应商文档核对基础地址 |
| 没有成功率或概率损失 | 当前推荐强度未经个人校准，不把它当成行动成功概率 |
| 资料没有命中 | 使用明确标题和关键词，拆成短段；当前不是语义向量检索 |
| 无法恢复到当前空间 | 恢复仅写入空目录，使用新的QONE_HOME，先保留现有备份 |
