# 个人系统融合：Life 实现路线

日期：2026-10-23。完整来源见 [q-one-core研究矩阵](https://github.com/aidless/q-one-core/blob/main/literature/MATRIX.zh-CN.md)，架构与阶段见[融合蓝图](https://github.com/aidless/q-one-core/blob/main/docs/SYNTHESIS_BLUEPRINT.zh-CN.md)。本文件列出待实现目标，当前为本地观察、累计维度分数和复盘提示原型。

## 1. 从真实问题定义量化

首个场景是“本周学习与专注安排”。用户声明目标和可用时间，系统记录有限观察、提出候选、保存用户选择并到期回看。采用个人信息学的阶段设计（S18），同时关注自主选择与记录负担（S19）。这些是产品设计依据，尚未证明本产品提升个人表现。

## 2. 指标定义先于评分

每个指标计划补齐：`definition_id/version`、单位、来源、量表含义、目标方向（增加/减少/区间）、可比较条件、采样频率、复盘窗口与缺失原因。当前归一化只支持“更大对应更高分”，不能直接用于压力、延误等指标；当前报告也没有时间窗口过滤。

定性记录与数值同等保留。睡眠质量自评、设备时长、完成情况是不同测量，不混用为同一个指标。记录不足时展示缺失，不填零、不推断人格或自动生成用户没有说过的价值观。

## 3. 候选融合

| 来源 | 借鉴 | 待实现内容 | 验收方法 |
| --- | --- | --- | --- |
| S18 个人信息学 | 准备—收集—整合—反思—行动 | 指标设置、固定窗口与更正入口 | 用户能完成一个完整周期并导出重算 |
| S19 自我决定理论 | 自主、反馈与使用负担 | 用户选择追踪项目、跳过/暂停与定性反馈 | 检查控制权与实际记录耗时，不宣称量表效度 |
| S20 系统思维 | 延迟、反馈与跨维度代价 | 行动时间范围、恢复约束与影响假设 | 复盘时区分事前假设和事后解释 |
| S24 多目标优化 | 约束与权衡集合 | 比较不同方案的时间、恢复、产出等维度 | 用户可调整权重并看到排序变化 |
| S21 因果方法 | 观察与干预的区别 | 时间顺序、混杂与反事实问题 | 未满足研究假设时只报告描述关联 |
| S25 单人研究指南 | 周期、偏离与结果记录 | 全文核查后再设计实验模板 | 不因完成记录就声称干预有效 |

每个维度保持独立。S24提供的方法不能替用户决定哪些目标值得追求。可以有用户自定的情境权重，必须保存版本与敏感性，不能默认为永久人生评分。

## 4. 待补的隐私与可复现边界

当前“脱敏导出”会去掉备注、原始source与decision_id，但仍保留数值、指标名和准确时间，并非匿名化；ID使用固定salt，可能跨导出关联。后续需设计每次导出的随机标识、时间粗化、字段预览以及私有映射策略。当前不应将默认导出描述为可直接公开分享。

观察记录需要更正/撤销事件，删除请求也要覆盖派生索引与备份策略；哈希链不等于不可篡改或加密。复盘报告计划保存指标版本、窗口和所用事件范围，避免一边更改量表一边比较历史趋势。

## 5. 实际使用验收

先选择一个约定窗口和少量指标，记录完成覆盖、缺失原因、每日填写负担、用户认为有用/无用的建议。覆盖率和采用率不作为生活质量的替代指标。初期20条决策只用于发现流程问题；统计推断与个人干预应另立设计。

随后才扩展到新领域。每次扩展都重新定义测量、授权字段和结果标准，不能把学习领域的证据自动用于健康、关系或财务决策。
