# v0.4 · Decision Studio

本次改版将首页组织为每日行动简报。先给出一个优先行动，再提供可展开的备选方向；减少统计卡片对注意力的占用。

## 信息与交互

- **行动提案**：行动名称、预计分钟数、已有依据、来源。模型尚未返回时展示“规则草案”，不把草案伪装成模型结果。
- **执行说明**：`first_step` 表示现在可以开始的一个操作；`done_when` 表示本次可检查的产出。长期目标完成与单次行动完成分别记录。
- **依据展开**：查看推荐理由、关联目标、原始完成标准、已知优先级和期限；模型建议的效果仍待实际核验。
- **今日计划容量**：每日预算减去当天已经安排的分钟数。分别呈现已安排、待采纳和留白，数值来自实际记录，不读取日历、不测量真实空闲。
- **今日安排**：采纳后才安排任务，保存当时的完整建议。可展开行动说明，勾选完成后触发下一次规划。
- **目标登记**：按活跃状态与优先级查看目标、完成标准和关联行动，不以任务勾选率替代长期目标完成率。

主色使用暖白、炭色与陶土色。图标使用一致的内联 SVG。网页无需第三方字体、图标服务、CDN 或前端构建工具；小屏使用收起的导航与单栏行动简报，支持减少动态效果的系统偏好。

## 推荐契约与兼容

Ollama 新输出必须包含非空的第一步和完成标准，每项最多600字符；格式不完整时保留明确标注的规则草案。已有待办名称继续保留。Laya负责选择候选，执行说明沿用规划规则，页面明确区分其来源。

采纳校验摘要包含标题、依据、第一步、完成标准、分钟数和输入版本。即使只改了第一步，旧采纳请求也会被拒绝。任务保留当次说明，后续建议不能覆盖已采纳的操作细节。已有 v1/v2 私有备份继续支持，新字段为可选兼容字段。

## 本机模型故障与 CPU 方式

本次环境检查无法访问显卡设备。Qwen3:8B 和 Qwen3:4B 的默认请求超时，Qwen3:4B 及最后一轮 Qwen3:1.7B 的 CPU 请求也超时，失败记录保留在 [模型超时回执](evidence/studio-model-timeout-20261024.json)。界面不会用虚构结果隐藏失败，也没有重启共享 Ollama 服务。

可在设置中选择已经下载的小模型，并按需在启动时指定 CPU：

```bash
QONE_OLLAMA_CPU_ONLY=1 bash scripts/run.sh
```

此环境变量仅影响自动推荐的 Ollama 请求，传入 `num_gpu=0`，HTTP连接与读写超时参数从120秒调整为240秒；不改变手动决策或 Laya。CPU 推理也可能超时，不能承诺统一速度或质量。默认模型仍为 `qwen3:8b`，既有设置不会被本次演示覆盖。

## 验收边界

桌面与390像素宽手机端使用独立合成空间检查。合成数据有明确横幅，与默认个人数据目录分开。检查内容包括来源展示、依据展开、备选项展开、采纳后的预算扣减与说明保留、完成状态、导航和目标表单。

应用35项自动化检查通过，并在隔离安装的 wheel 中重复通过。新增覆盖：行动字段的类型/长度约束、采纳后说明保留、仅修改第一步时拒绝旧采纳、缺少执行说明时拒绝模型输出。它们证明接口与状态处理，不证明推荐一定合适，更不证明个人收益。
